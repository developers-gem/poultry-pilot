# PoultryPilot data model

How the MongoDB collections fit together and the rules every collection follows. The field-by-field reference is the generated [data dictionary](data-dictionary.md); schemas live in `services/api/src/adapters/mongo/models/`.

63 collections: the 56 product collections, plus 7 for authentication and infrastructure (`sessions`, `refresh_tokens`, `one_time_tokens`, `sync_changes`, `idempotency_keys`, `counters`, `media_assets`). 103 secondary indexes, each tied to a named query.

## Conventions

| Concern | Rule |
| --- | --- |
| IDs | `_id` is a UUIDv7 string, generated by the client or server. Offline-created records keep their id after sync. All references are these strings |
| Business dates | Farm-local `YYYY-MM-DD` strings (`date`, `dueDate`, `hatchDate`), interpreted in the farm's timezone |
| Instants | UTC `Date` (`createdAt`, `checkInAt`, `sentAt`) |
| Money | `{ amountMinor, currency }`: integer minor units plus ISO 4217 code. Never floats |
| Units | Canonical metric in the field name: `quantityKg`, `weightsG`, `litres`, `temperatureMinC`. Conversion to imperial happens for display only |
| Enums | Lowercase snake_case values from `packages/constants`; the same lists feed Mongoose, Zod and clients |
| Unknown fields | Rejected (`strict: "throw"`), so a typo in code fails loudly instead of storing junk |
| Standard fields | Added by `defineCollection` according to ownership (below): `farmId`, `createdBy`, `updatedBy`, `createdAt`, `updatedAt`, `version`, `deletedAt`, `deletedBy` |

## Ownership

| Ownership | Collections | Standard fields | Access rule |
| --- | --- | --- | --- |
| Farm | 45 collections, e.g. flocks, daily_records, inventory_lots, hatchery_batches, incomes, money_accounts, sync_operations | `farmId`, `createdBy` (required), `updatedBy`, `version`, soft delete unless append-only | Every query includes `farmId`; the `requireFarmScope` plugin throws if it is missing. Indexes start with `farmId` |
| Tenant | farms | `createdBy`, `version`, soft delete | Read by `_id` after a membership check |
| User | users, sessions, refresh/one-time tokens, notifications, push_devices, notification_preferences, training_progress | per collection | Queried by `userId` of the signed-in person |
| Global | training_courses, articles, glossary_terms, market_prices, weather_cache, weather_observations (location-keyed) | `createdBy`/`updatedBy` optional (staff or import job) | Readable by any signed-in user; written by staff tools or jobs |
| System | audit_logs, idempotency_keys, counters | none (actor is a domain field, e.g. `actorUserId`) | Written by the API only |

`createdBy` is required on every farm record people create. It is absent only where no person writes the record (sessions, tokens, sync, audit, cache, notifications) — listed and enforced in `schema.test.ts`.

### Reads that deliberately span farms

These are the only queries allowed without `farmId`. They pass `setOptions({ crossFarm: true })` and are covered by their own indexes:

| Query | Index |
| --- | --- |
| Marketplace browse and "near me" (active listings only) | `market_listings` (status, category, createdAt), (location 2dsphere, status) |
| A marketplace buyer's purchases from all sellers | `orders` (buyerUserId, createdAt), partial |
| A person's memberships for `/me` and the farm switcher | `farm_members` (userId, status) |
| Accepting an invitation before membership exists | `farm_members` (inviteTokenHash) |

## Source of truth and derived data

Each fact has one home. Some values are also kept as **derived snapshots** for fast reads. These are written only by the owning service, in the same transaction as the change that affects them, and can always be rebuilt from their sources.

| Derived value | Maintained by | Rebuilt from |
| --- | --- | --- |
| `flocks.population` (placed, transferred in, mortality, culled, sold, moved out, adjustments, alive) | FlockService | `flock_events` (the flock ledger) |
| `bird_weights.stats` | the document itself on save (domain `weighSessionStats`) | `bird_weights.weightsG` |
| `daily_records.summary` | DailyRecordService | the record's linked rows in `flock_events`, `feed_consumption`, `water_records`, `egg_records`, `health_records` |
| `daily_records.houseId`, `flockType` | DailyRecordService on creation | the flock on that day (type is immutable) |
| `inventory_items.stock` (quantity, value) | InventoryService | `inventory_lots.quantityRemaining × unitCost` |
| `inventory_lots.quantityRemaining` | InventoryService | `inventory_transactions` for the lot |
| `feed_consumption.allocations`, `cost` | FeedService at issue time | the FEFO lots used and their unit costs |
| `water_records.flags`, `baselineLitres` | DailyRecordService on save | the litres, pH and dissolved solids against the farm limits and the previous days |
| Egg stock per grade | aggregation, no snapshot | sum of `egg_inventory.quantityDelta` |
| `chicks.remaining` | HatcheryService / FlockService / OrderService | `chicks.quantity` − placements − chick sales |
| `hatchery_batches.results` (counts and rates), `status` | HatcheryService in the same transaction as each event | `hatchery_events.counts` (effective, after reversals) |
| `health_records.treatments[].endDate`, `withdrawal*Until` | HealthService on save | start + duration; end + withdrawal days (treatment override, else the medicine's catalog entry; none if neither) |
| `egg_records.withheldUntil` | HealthService when treatments or eggs change | egg withdrawal windows of the flock's treatments |
| `visitors.downtimeHours`, `flags` | BiosecurityService at check-in | last poultry contact vs check-in, the farm's `visitorDowntimeHours`, declaration checklist |
| `expenses` / `incomes` `.net`, `.tax`, `.amountPaid`, `.status` | FinanceService | the entered amount and tax; `transactions` with `documentId` = the document |
| Money account balance | FinanceService (computed, not stored) | opening balance + `transactions` for the account |
| `market_listings.quantityAvailable` | MarketService on accept and cancel | listing quantity − accepted, undelivered orders |
| `orders.amountPaid`, `orders.paymentStatus`, `orders.incomeId` | MarketService | `order_payments` / the order's income |
| Vaccination "overdue" | never stored | `status = scheduled` and `dueDate` < farm-local today |

## What writes what

When a record changes, the service writes these in **one transaction** (MongoDB replica set). It also writes an `audit_logs` entry and, for synced entities, a `sync_changes` entry.

| Action | Writes |
| --- | --- |
| Place chicks in a flock | `flock_events` (placement) → `flocks.population`; draws down `chicks.remaining` if from a lot; `expenses` for bought chicks (with the money module) |
| Save a daily record | `daily_records` (with derived `summary`) + `flock_events` (mortality, cull, weighing; reversals of the record's previous ones) + `feed_consumption` + `water_records` + `egg_records` + `egg_inventory` + `health_records` (observations) → `flocks.population`; only sections that changed are rewritten. See [daily-operations.md](daily-operations.md) |
| Delete a daily record | reversals in `flock_events` and `egg_inventory`; soft delete of the record's feed, water, egg and observation records and of the record |
| Upload a photo | object storage + `media_assets` |
| Transfer, split or merge birds | paired `flock_events` on both flocks (with cost and weight) → both snapshots; a split creates the new `flocks` document; a merge closes the source |
| Sell birds, adjust, weigh, close | `flock_events` → `flocks.population` (`bird_weights` for individual weights) |
| Save an egg record | `egg_records` + `egg_inventory` (collected, and broken as a negative movement); editing it reverses and re-posts by `sourceId` |
| Feed eaten or wasted (daily record or `/feed/consumption`) | `feed_consumption` + `inventory_transactions` (issue or wastage per lot) → `inventory_lots.quantityRemaining`, `inventory_items.stock`; alerts re-evaluated |
| Purchase (any stock item) | `inventory_lots` + `inventory_transactions` (receipt) → `inventory_items.stock`; alerts re-evaluated; `expenses` when the money module exists |
| Stock count | `inventory_transactions` (adjustment), and an `inventory_lots` row for a surplus |
| Place a flock from a chick lot | `chicks.remaining`, `placedFlockIds` + the placement event |
| Pay or refund a bill or income | `transactions` (payment or refund) → document `amountPaid/status` |
| Transfer between accounts | two `transactions` (kind transfer) sharing `transferGroupId` |
| Recurring bill falls due | `expenses` (unique per bill and due date), then `recurring_expenses.nextDueDate` |
| Inventory purchase | also an `expenses` purchase bill (sourceId = lot) |
| Bird sale | also an `incomes` receivable (sourceId = sale event), unless the sale came from an order |
| Give a vaccination | `vaccinations` (done, batches and expiry from lots) + `inventory_transactions` (issue) → `inventory_items.stock`; alert resolved |
| Record a treatment | `health_records` (treatments with withdrawal dates) + `inventory_transactions` (issue) + `egg_records.withheldUntil`; `withdrawal_active` alert |
| Check a visitor in | `visitors` + `tasks` (corrective actions for failed declaration items) + alerts (downtime, failed checklist) |
| Biosecurity log | `biosecurity_logs` + `inventory_transactions` for products + `tasks` / alerts for problems found |
| Complete a cleaning schedule | `biosecurity_logs` + `cleaning_tasks.lastDoneDate/nextDueDate` |
| Move equipment | `equipment_movements` + `equipment.houseId`; corrective action if not disinfected |
| Any alert raised (any module) | checked against `alert_rules` (on/off, scope, severity) → `alerts` → `notifications` (in-app delivered; push and email queued) |
| Delivery worker | `notifications.status/attempts/nextAttemptAt`; invalid `push_devices` disabled |
| Weather fetched | `weather_cache` (1 hour) + `weather_observations` (past days upserted) |
| Accept an order | `orders.status` + `market_listings.quantityAvailable` (reserved) + `incomes` receivable |
| Deliver an order | `orders.status/delivery` + stock: `egg_inventory` (sold), `flock_events` (sale with orderId) or `chicks.remaining` |
| Cancel an order | `orders.status` + reservation returned + receivable cancelled (refused while payments stand) |
| Receive an order payment | `order_payments` + `transactions` → income `amountPaid` → `orders.amountPaid/paymentStatus` |
| Set a hatchery batch | `hatchery_batches` + `hatchery_events` (set) + `egg_inventory` (own-flock hatching eggs leave stock) |
| Candling, transfer, hatch | `hatchery_events` → `hatchery_batches.results/status` |
| Grade chicks | `hatchery_events` + a `chicks` lot (costed per saleable chick) |
| Deliver a chick order | `orders.status/statusHistory/deliveredDate` + `chicks.remaining` |
| Chick arrival (ChickStart) | `chick_arrivals` + `flocks` + placement `flock_events` + `chicks.remaining`, one transaction |
| Brooder check | `brooder_checks` (+ `brooding_conditions` alert when flagged) |
| Alert job finds a problem | `alerts` (unique dedupKey) + `notifications` per recipient and channel |
| Offline mutation pushed | `sync_operations` (outcome, exactly once) + whatever the command writes |

> **Change with FeedWise (D50):** feed is an `inventory_items` row of category `feed`; purchases of any item are `inventory_lots`. The separate `feed_items` and `feed_purchases` collections were removed so there is one catalog and one stock ledger. See [feedwise-inventory.md](feedwise-inventory.md).
>
> **Change with the flock engine (D35):** deaths and culls are `flock_events`, not fields on `daily_records`. A daily record posts them as events linked by `dailyRecordId`. The flock ledger is therefore the only place a bird-count change is stored. See [flock-engine.md](flock-engine.md).

## Corrections, deletion and retention

- **Editable records** (flocks, daily records, expenses…) are soft-deleted: `deletedAt` is set, the record stays for audit and sync, and queries filter with `deletedAt: null`.
  - That filter matches both missing and null. Never use `deletedAt: { $exists: false }`: new records store `deletedAt: null`. The repository contract test caught exactly this bug.
- **Unique constraints ignore soft-deleted records** ("live records only" in the dictionary), so a deleted house name can be reused.
- **Append-only ledgers** (`flock_events`, `egg_inventory`, `inventory_transactions`, `transactions`, `order_payments`, `hatchery_events`, `equipment_movements`, `sync_changes`) are never updated or deleted. A mistake is fixed by a new entry whose `reversalOf` points at the original, so balances and history always agree.
- **Retention by TTL index:**

  | Collection | Kept for |
  | --- | --- |
  | `sessions` | 30 days after expiry |
  | `refresh_tokens` | 7 days after expiry |
  | `one_time_tokens` | 1 day after expiry |
  | `idempotency_keys` | 7 days |
  | `sync_operations` | 90 days |
  | `notifications` | 180 days |
  | `weather_cache` | until expiry |

  Audit logs and farm data have no TTL.

## Embed or reference

| Embedded | Why |
| --- | --- |
| Sample weights in `bird_weights` | Read only with their session; capped at 2,000 |
| Lines and status history in `orders` | Read with the order; capped at 50 lines |
| Lessons in `training_courses` | Read with the course; a few per course |
| Treatment in `health_records`, results in `hatchery_batches` | One per parent document |
| Checklists in `cleaning_tasks`, `biosecurity_logs` | Small, owned by the parent |

Everything that grows without bound, or is queried on its own, has its own collection: feed consumption, egg movements, payments, flock events, hatchery events, transactions.

## Verification

- `schema.test.ts`, run in every build, checks that:
  - every requested collection exists
  - standard fields are present
  - every reference resolves
  - enums come from the constants
  - farm indexes start with `farmId` (exceptions listed above)
  - no index is a redundant prefix of another
  - the tenancy guard is active on every farm-owned model
  - computed fields and validators behave as described
- `data-dictionary.test.ts` fails if the dictionary is out of date.
- `repositories.contract.test.ts` runs the repository contract against a live server.
- All indexes were created against FerretDB, which speaks the MongoDB protocol, except 18 that use features FerretDB lacks: TTL, partial, 2dsphere and text indexes. CI creates them on MongoDB 7.
